    vLLM 引擎参数总览（Ascend 语境）¶

    本页表格由 scripts/generate_tables.py 从 data/engine-args.yaml 自动生成，请勿手改表格区域。

    收录原则：只收录 vLLM-Ascend 官方文档（模型教程、特性指南、quick_start、FAQs）中真实出现过的参数；每个参数都在 vLLM 源码（arg_utils.py/cli_args.py/config/）中有定义。共 78 个参数，按功能分 9 类。

    这里的参数指 vllm serve 顶层命令行参数（--xxx），由 vLLM 主仓定义、跨平台通用；vLLM-Ascend 插件专有的配置键（AscendConfig 字段，经 --additional-config JSON 传入）见特性开关总览。

    与官方文档的关系¶

    • vLLM 官方参数文档覆盖全部 270+ 个参数；本表聚焦 Ascend 部署语境（官方教程中的实际用法、推荐值、注意事项）。
    • 每个参数的"官方文档出处"链接到具体的 vLLM-Ascend 教程页面，可点击查看原始命令行上下文。
    • 默认值取自 vLLM 源码 dataclass 定义（ParallelConfig/ModelConfig/VllmConfig 等），非文档文字描述。
    • 重点参数有独立详情页（见带链接的参数名）。

    KV 缓存与内存¶

    参数 类型 默认值 说明 官方文档出处
    --cp-kv-cache-interleave-size int None CP 模式下 KV cache 的交错粒度。调优参数，默认 1 通常够用。 docs×5
    --block-size int None KV cache block 大小。默认 None（自动，通常 16）；DeepSeek-V4-Pro 教程显式设 32，KVPP 等特性另有取值。 docs×13
    --enable-prefix-caching bool None 前缀缓存。默认 None（按模型自动判断）；PD 分离教程中 decode 节点显式用 --no-enable-prefix-caching。 docs×34
    --kv-cache-dtype CacheDType "auto" KV cache 量化类型（如 fp8、int8）。Ascend 量化模型教程常用以节省显存。 docs×15
    --kv-cache-memory-bytes int None KV cache 显存上限（字节）。比 gpu-memory-utilization 更精细的替代。 docs×2

    调度与内存¶

    参数 类型 默认值 说明 官方文档出处
    --async-scheduling bool None 异步调度。默认 None（自动）；部分官方教程显式开启以提升吞吐。 docs×16
    --disable-hybrid-kv-cache-manager bool "(" 禁用混合 KV cache 管理器。vLLM 默认按模型自动判断，一般不手动设。 docs×5
    --enable-chunked-prefill bool None 分块 prefill。vLLM main 默认开启（SchedulerConfig 默认 True），按 max_num_batched_tokens 剩余额度切分；encoder-decoder 模型自动禁用。 docs×13
    --gpu-memory-utilization float None 模型执行器显存占比（0–1）。默认 None → 可扩展 KV cache 时解析为 1.0，否则 0.92（vLLM main 源码）；官方教程多显式设 0.80–0.90。 docs×46
    --long-prefill-token-threshold int 0 长 prefill token 阈值。超过该值的请求走分块路径。 docs×2
    --mamba-ssm-cache-dtype MambaDType "auto" Mamba/SSM 模型的 cache dtype。默认为 auto。 docs×4
    --max-model-len int None 模型最大上下文长度。不设则从模型 config 自动推断。长文本场景必须显式设置。 docs×52
    --max-num-batched-tokens int None 单次迭代最大 token 数。默认 None（自动）；动态分块流水线并行（CPP）指南的调优搜索空间为 [8192, 16384, 24576, 32768]。 docs×50
    --max-num-seqs int None 单次迭代最大处理序列数（并发上限）。默认 None（自动）；官方教程实测取值 12–128，按显存与延迟权衡。 docs×47

    编译与图¶

    参数 类型 默认值 说明 官方文档出处
    --attention-config AttentionConfig "AttentionConfig()" 注意力后端及配置。子键 indexer_kv_dtype 是 Lightning Indexer 稀疏注意力的 KV dtype（fp8/int8/mxfp4），v0.30.0 起分别派生 LI-C8/LI-C4 布局；与 --kv-cache-dtype 配对使用，P/D 两侧取值须一致。 docs×9
    --compilation-config CompilationConfig "CompilationConfig()" torch.compile 与 CUDA Graph 捕获配置。Ascend 官方教程中常配 cudagraph_capture_sizes 提升首 token 延迟。 docs×53
    --enforce-eager bool false 强制 eager 模式（跳过 CUDA Graph）。首次部署或调试时用；生产关闭以获取图捕获性能。 docs×21

    --lora-modules list[LoRAModulePath] None LoRA 模块列表（JSON）。与 enable-lora 配合。 docs×2
    --max-lora-rank MaxLoRARanks 16 LoRA 最大 rank。限制可加载的 LoRA 适配器规模。 docs×2

    部署建议¶

    场景 关键参数组合（来自官方教程）
    单卡 A2 小模型 --tensor-parallel-size 1 --max-model-len 32768 --gpu-memory-utilization 0.9 --max-num-seqs 32
    MoE 大模型 EP --enable-expert-parallel --data-parallel-size N --tensor-parallel-size M（M×DP = 专家数）
    长上下文 --max-model-len 大值 --enable-chunked-prefill --max-num-batched-tokens 16384+
    PD 分离 每个节点 --kv-transfer-config '{...}' --enable-prefix-caching/--no-enable-prefix-caching
    生产服务 关闭 --enforce-eager（启用 CUDA Graph），配 --compilation-config 捕获策略

    完整命令示例与逐模型部署指南见官方教程：Model Deployment Tutorials。

    数据核验方式¶

    • 参数存在性：全部 78 个参数在 vLLM 源码 add_argument() 中有定义。
    • Ascend 语境：每个参数至少在 vLLM-Ascend 官方文档的 1 个真实命令行中出现（doc_count 列给出文件数）。
    • 默认值：从 vLLM 源码 EngineArgs/FrontendArgs dataclass 及 vllm/config/*.py 提取；None 表示"自动推断"或"不设"。
    • 说明：中文说明为官方 help 文本的忠实翻译 + 官方教程实际用法补充；标注"官方教程"的内容均可溯源。
